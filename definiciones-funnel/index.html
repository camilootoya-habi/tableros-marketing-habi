Definiciones del funnel

Cómo se cuantifica cada paso del funnel de sellers en Colombia y México: la tabla fuente, la query y la regla de medición. Todo corre en BigQuery, proyecto sellers-main-prod. CO y MX son esquemas distintos (CO en español, MX en inglés): no basta con cambiar el dataset.

Cada fila trae su antifunnel: los que llegaron a la etapa anterior y no pasaron a esta, abiertos por su estado actual MM | INMO (concatenado, id y nombre). Así se ve en qué producto quedó cada lead y dónde hay oportunidad.

3 · Completos
De los registros (fila 2), cuántos tienen las 5 variables que el backbone exige para evaluar un lead: área, baños, habitaciones, garajes y antigüedad. No depende del producto (MM o INMO) ni del estado del lead.
Propuesta 		Tabla Las 5 variables viven en el inmueble: co_rds_staging.habi_db_tabla_inmueble_v2 (area, banos, num_habitaciones, garajes, anos_antiguedad). Query 
SELECT
  DATE_TRUNC(DATE(n.fecha_creacion), MONTH) AS mes,
  COUNT(DISTINCT n.id) AS registros,
  COUNT(DISTINCT IF(
      p.area IS NOT NULL
      AND p.banos IS NOT NULL
      AND p.num_habitaciones IS NOT NULL
      AND p.garajes IS NOT NULL
      AND p.anos_antiguedad IS NOT NULL,
    n.id, NULL)) AS completos
FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_negocio_inmueble` n
JOIN `sellers-main-prod.co_rds_staging.habi_db_tabla_inmueble_v2` p
  ON p.id = n.inmueble_id
WHERE p.fuente_id IN (3, 7, 20, 35, 39, 47)   -- 6 fuentes de marketing
GROUP BY mes
Cómo se mide
  • Completo = las 5 variables no nulas. Es la regla del backbone (global_completeness_service_co.dmn): un 0 cuenta como dato presente.
  • Se leen los valores actuales del inmueble. Si el call center o Gabi completan un dato después, el lead pasa a completo, y las cohortes viejas suben con el tiempo.
  • El 100% de los calificados (20, 63) es completo: la regla es consistente con el backbone.

Antifunnel

Registros que no son completos, por su estado actual MM | INMO. Se agrupan según si algún producto todavía puede avanzar:

  • Oportunidad: al menos un producto no lo ha descartado (sigue en 7 incompleto o en proceso). Completarlo le sirve a ese producto.
  • Descartado en ambos: los dos productos ya lo sacaron. Completarlo no cambia nada.

WITH
-- catálogo de estados (mismos ids para MM e INMO)
cat AS (
  SELECT id, estado FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_estados`
),
-- registros no completos con su estado actual MM e INMO
no_completos AS (
  SELECT n.id, n.last_estado_id AS mm, n.last_state_id_real_estate AS inmo
  FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_negocio_inmueble` n
  JOIN `sellers-main-prod.co_rds_staging.habi_db_tabla_inmueble_v2` p
    ON p.id = n.inmueble_id
  WHERE p.fuente_id IN (3, 7, 20, 35, 39, 47)
    AND DATE(n.fecha_creacion) BETWEEN '2026-08-01' AND '2026-08-31'   -- cohorte
    AND NOT (p.area IS NOT NULL AND p.banos IS NOT NULL AND p.num_habitaciones IS NOT NULL
             AND p.garajes IS NOT NULL AND p.anos_antiguedad IS NOT NULL)
),
-- ¿el producto ya lo descartó? (duplicado, call center, regla del inmueble o sin precio)
clasif AS (
  SELECT
    id, mm, inmo,
    IFNULL(mm, -1)   IN (1,4,5,6,8,9,10,11,12,15,16,33,34,36,38,51,55,56,57,59,61,64,70,71,72,73) AS mm_descartado,
    IFNULL(inmo, -1) IN (1,4,5,6,8,9,10,11,12,15,16,33,34,36,38,51,55,56,57,59,61,64,70,71,72,73) AS inmo_descartado
  FROM no_completos
)
SELECT
  CONCAT(IFNULL(CAST(c.mm AS STRING), '-'), ' ', IFNULL(cm.estado, ''), ' | ',
         IFNULL(CAST(c.inmo AS STRING), '-'), ' ', IFNULL(ci.estado, '')) AS estado_mm_inmo,
  CASE
    WHEN NOT c.mm_descartado AND NOT c.inmo_descartado THEN 'oportunidad: MM e INMO'
    WHEN NOT c.mm_descartado THEN 'oportunidad: solo MM'
    WHEN NOT c.inmo_descartado THEN 'oportunidad: solo INMO'
    ELSE 'descartado en ambos'
  END AS grupo,
  COUNT(DISTINCT c.id) AS leads
FROM clasif c
LEFT JOIN cat cm ON cm.id = c.mm
LEFT JOIN cat ci ON ci.id = c.inmo
GROUP BY estado_mm_inmo, grupo
ORDER BY leads DESC

4 · Ever calificados
De los registros (fila 2), cuántos pasaron alguna vez por un estado de calificado del backbone, sin importar dónde estén hoy. Se mide por producto: MM, INMO y calificado en cualquiera de los dos.
Propuesta 		Tablas
  • MM: co_rds_staging.habi_db_tabla_historico_estado_v2 → negocio_id, estado_id IN (20, 63), fecha_actualizacion.
  • INMO: co_rds_staging.habi_db_history_state_real_estate → deal_id, state_id = 20, date_create.
Query 
WITH
-- registros de las 6 fuentes (fila 2)
registros AS (
  SELECT n.id, DATE_TRUNC(DATE(n.fecha_creacion), MONTH) AS mes
  FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_negocio_inmueble` n
  JOIN `sellers-main-prod.co_rds_staging.habi_db_tabla_inmueble_v2` p
    ON p.id = n.inmueble_id
  WHERE p.fuente_id IN (3, 7, 20, 35, 39, 47)
    AND DATE(n.fecha_creacion) >= '2026-06-01'   -- inicio de la cohorte
),
-- primera calificación MM por negocio
cal_mm AS (
  SELECT negocio_id AS id, MIN(fecha_actualizacion) AS fecha_cal_mm
  FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_historico_estado_v2`
  WHERE estado_id IN (20, 63)
    AND fecha_actualizacion >= '2026-06-01'      -- mismo corte
  GROUP BY id
),
-- primera calificación INMO por negocio
cal_inmo AS (
  SELECT deal_id AS id, MIN(date_create) AS fecha_cal_inmo
  FROM `sellers-main-prod.co_rds_staging.habi_db_history_state_real_estate`
  WHERE state_id = 20
    AND date_create >= '2026-06-01'
  GROUP BY id
)
SELECT
  r.mes,
  COUNT(DISTINCT r.id) AS registros,
  COUNT(DISTINCT IF(m.id IS NOT NULL, r.id, NULL)) AS ever_cal_mm,
  COUNT(DISTINCT IF(i.id IS NOT NULL, r.id, NULL)) AS ever_cal_inmo,
  COUNT(DISTINCT IF(m.id IS NOT NULL OR i.id IS NOT NULL, r.id, NULL))
    AS ever_cal_cualquiera
FROM registros r
LEFT JOIN cal_mm m ON m.id = r.id
LEFT JOIN cal_inmo i ON i.id = r.id
GROUP BY r.mes
Cómo se mide
  • Calificado MM = 20 o 63; calificado INMO = solo 20. El 36 (sin comparables) y el 73 (sin precio automático) no son calificado.
  • Por cohorte de registro (fecha_creacion), igual que las filas 2 y 3. La fecha de calificación (MIN) queda disponible para medir tiempos o volumen semanal.
  • MM e INMO no se suman: un lead puede calificar en los dos. "Cualquiera" es la unión.
  • Cuentan aunque después hayan cambiado de estado (descartados, duplicados): calificaron.
  • ⚠ El historial INMO de CO arranca el 2026-03-12: las cohortes anteriores subcuentan el ever INMO.

WITH
cat AS (
  SELECT id, estado FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_estados`
),
-- completos de la cohorte con su estado actual MM e INMO
completos AS (
  SELECT n.id, n.last_estado_id AS mm, n.last_state_id_real_estate AS inmo
  FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_negocio_inmueble` n
  JOIN `sellers-main-prod.co_rds_staging.habi_db_tabla_inmueble_v2` p
    ON p.id = n.inmueble_id
  WHERE p.fuente_id IN (3, 7, 20, 35, 39, 47)
    AND DATE(n.fecha_creacion) BETWEEN '2026-08-01' AND '2026-08-31'   -- cohorte
    AND p.area IS NOT NULL AND p.banos IS NOT NULL AND p.num_habitaciones IS NOT NULL
    AND p.garajes IS NOT NULL AND p.anos_antiguedad IS NOT NULL
),
-- negocios que alguna vez calificaron en MM o en INMO
calificados AS (
  SELECT negocio_id AS id
  FROM `sellers-main-prod.co_rds_staging.habi_db_tabla_historico_estado_v2`
  WHERE estado_id IN (20, 63) AND fecha_actualizacion >= '2026-08-01'
  UNION DISTINCT
  SELECT deal_id
  FROM `sellers-main-prod.co_rds_staging.habi_db_history_state_real_estate`
  WHERE state_id = 20 AND date_create >= '2026-08-01'
)
SELECT
  CONCAT(IFNULL(CAST(c.mm AS STRING), '-'), ' ', IFNULL(cm.estado, ''), ' | ',
         IFNULL(CAST(c.inmo AS STRING), '-'), ' ', IFNULL(ci.estado, '')) AS estado_mm_inmo,
  COUNT(DISTINCT c.id) AS leads
FROM completos c
LEFT JOIN calificados q ON q.id = c.id
LEFT JOIN cat cm ON cm.id = c.mm
LEFT JOIN cat ci ON ci.id = c.inmo
WHERE q.id IS NULL                      -- nunca calificó en ningún producto
GROUP BY estado_mm_inmo
ORDER BY leads DESC

SELECT
  r.mes,
  COUNT(DISTINCT r.id) AS registros,
  COUNT(DISTINCT IF(m.id IS NOT NULL, r.id, NULL)) AS ever_cal_mm,
  COUNT(DISTINCT IF(i.id IS NOT NULL, r.id, NULL)) AS ever_cal_inmo,
  COUNT(DISTINCT IF(m.id IS NOT NULL OR i.id IS NOT NULL, r.id, NULL))
    AS ever_cal_cualquiera
FROM registros r
LEFT JOIN cal_mm m ON m.id = r.id
LEFT JOIN cal_inmo i ON i.id = r.id
GROUP BY r.mes

WITH
cat AS (
  SELECT id, state AS estado FROM `sellers-main-prod.mx_rds_staging.habi_db_state`
),
-- completos de la cohorte con su estado actual MM e INMO
completos AS (
  SELECT d.id, d.last_state_id AS mm, d.last_state_id_real_estate AS inmo
  FROM `sellers-main-prod.mx_rds_staging.habi_db_property_deal` d
  JOIN `sellers-main-prod.mx_rds_staging.habi_db_property` p
    ON p.id = d.property_id
  WHERE p.source_id IN (3, 7, 35, 39, 46, 47)
    AND DATE(d.date_create) BETWEEN '2026-08-01' AND '2026-08-31'      -- cohorte
    AND p.area IS NOT NULL AND p.bath IS NOT NULL AND p.room_num IS NOT NULL
    AND p.garage IS NOT NULL AND p.years_old IS NOT NULL
),
-- deals que alguna vez calificaron en MM o en INMO
calificados AS (
  SELECT deal_id AS id
  FROM `sellers-main-prod.mx_rds_staging.habi_db_history_state`
  WHERE state_id IN (20, 63) AND date_create >= '2026-08-01'
  UNION DISTINCT
  SELECT deal_id
  FROM `sellers-main-prod.mx_rds_staging.habi_db_history_state_real_estate`
  WHERE state_id = 20 AND date_create >= '2026-08-01'
)
SELECT
  CONCAT(IFNULL(CAST(c.mm AS STRING), '-'), ' ', IFNULL(cm.estado, ''), ' | ',
         IFNULL(CAST(c.inmo AS STRING), '-'), ' ', IFNULL(ci.estado, '')) AS estado_mm_inmo,
  COUNT(DISTINCT c.id) AS leads
FROM completos c
LEFT JOIN calificados q ON q.id = c.id
LEFT JOIN cat cm ON cm.id = c.mm
LEFT JOIN cat ci ON ci.id = c.inmo
WHERE q.id IS NULL                      -- nunca calificó en ningún producto
GROUP BY estado_mm_inmo
ORDER BY leads DESC

Por qué id y no nid

En ago-2026 (todas las fuentes, antes del filtro) el conteo por id es igual al total de filas en los dos países. nid es casi igual, pero algunos negocios no lo tienen y se perderían:

Para cruzar con tablas de funnel o HubSpot, que viven a nivel nid, se usa nid como llave de join. El conteo de registros se hace por id.
